\begin{frame}{Three ideas about graph neural networks}
  \begin{enumerate}
    \setlength{\itemsep}{1.1em}
    \item Each node makes a \alert{summary of its neighbors}, then updates itself.
    \item Each layer extends the view of a node by \alert{one hop}. Two or three
          layers is the usual optimum.
    \item \alert{Graph construction} decides how a GNN performs. The layer
          architecture matters less.
  \end{enumerate}
\end{frame}

\begin{frame}{Flattening fails: the number of objects changes}
  \vspace{1.2em}
  \begin{center}
    \Large
    A fixed input dimension cannot take a \alert{variable number of objects}.
  \end{center}
  \vspace{1.4em}
  \begin{itemize}
    \setlength{\itemsep}{0.7em}
    \item A DPI-Net scene has one node per particle, and that count differs per object.
    \item A learned simulator is tested on more particles than any training scene had.
    \item A scene graph has one node per object in the room, and the room changes.
  \end{itemize}
  \vfill

  \end{center}

\begin{frame}{One idea: each node makes a summary of its neighbors, then repeats}
  \vspace{-0.4em}
  \begin{center}
    \begin{tikzpicture}[scale=0.92, every node/.style={transform shape},
      nb/.style={circle, draw=acc2, fill=acc2!15, minimum size=8mm,

                 font=\small, inner sep=0pt},
      msg/.style={-{Latex[length=2mm]}, acc2, thick}]

      \node[me] (v) at (0,0) {$\hv$};
      \node[nb] (u1) at (150:2.3) {$h_{u_1}$};
      \node[nb] (u2) at ( 90:2.3) {$h_{u_2}$};
      \node[nb] (u3) at ( 30:2.3) {$h_{u_3}$};
      \node[nb] (u4) at (270:2.3) {$h_{u_4}$};

      \foreach \u in {u1,u2,u3,u4} \draw[msg] (\u) -- (v);
      \node[color=acc2, font=\scriptsize, anchor=north east] at (-0.95,0.32)
        {message};

      \node<2->[draw=acc, fill=white, rounded corners=2pt, font=\scriptsize,
            right=3.0cm of v, align=center] (agg)
        {sum / mean / max\\ \color{dim}(order-independent)};
      \draw<2->[-{Latex[length=2mm]}, acc, thick] (v) -- (agg);

      \node<3->[draw=good, fill=good!8, rounded corners=2pt, font=\scriptsize,
            below=0.9cm of agg, align=center] (upd)
        {small MLP\\ \color{dim}update the node};
      \draw<3->[-{Latex[length=2mm]}, good, thick] (agg) -- (upd);
    \end{tikzpicture}
  \end{center}
  \vspace{-0.3em}
  \begin{enumerate}
    \item<1-> Each neighbor \alert{sends a message}.
    \item<2-> The node combines them with an \alert{order-independent} function: sum, mean or max.
    \item<3-> The node \alert{updates its own vector} with a small MLP. The layer repeats $L$ times.
  \end{enumerate}
\end{frame}

\begin{frame}{The message-passing equation, in three clicks}
  \vspace{1.6em}
  \begin{center}
    \large
    \only<1>{$\hv \;\leftarrow\; \textcolor{dim}{\mathrm{UPDATE}\Big(\hv,\;
      \mathrm{AGG}\big\{}\;\textcolor{acc}{\mathrm{MSG}(\hv, \hu, e_{uv})}\;
      \textcolor{dim}{:\; u \in \Nv \big\}\Big)}$}
    \only<2>{$\hv \;\leftarrow\; \textcolor{dim}{\mathrm{UPDATE}\Big(\hv,\;}
      \textcolor{acc}{\mathrm{AGG}\big\{}\;\mathrm{MSG}(\hv, \hu, e_{uv})\;
      \textcolor{acc}{:\; u \in \Nv \big\}}\textcolor{dim}{\Big)}$}
    \only<3->{$\hv \;\leftarrow\; \textcolor{acc}{\mathrm{UPDATE}\Big(}\hv
      \textcolor{acc}{,}\;
      \mathrm{AGG}\big\{\;\mathrm{MSG}(\hv, \hu, e_{uv})\;:\; u \in \Nv \big\}
      \textcolor{acc}{\Big)}$}
  \end{center}
  \vspace{1.8em}
  \begin{center}
    \only<1>{\alert{A neighbor $u$ sends a message to $v$.} The message can use
      the features of $v$, the features of $u$, and \emph{the edge feature $e_{uv}$}.}
    \only<2>{\alert{AGG combines all the messages} with a sum, mean or max.
      Because that function ignores order, the layer is permutation invariant.}
    \only<3>{\alert{UPDATE is a small MLP} on $(h_v,\ \text{summary})$.
      That completes one layer.}
    \only<4>{\alert{A GNN is $L$ of these layers}, stacked.}
  \end{center}
  \vspace{1.2em}
  \onslide<4->{\begin{center}\small\color{dim}
    GCN in one line: $H \leftarrow \hat{A}\,(H W)$, with
    $\hat{A} = D^{-1/2}(A+I)D^{-1/2}$, a normalized neighbor average, then a
    linear map.
  \end{center}}
\end{frame}
\note{This is the only equation in the talk. Read it left to right, out loud,

Emphasize: $e_{uv}$ is the edge feature. In robotics that is the

\begin{frame}{Three task types, three readouts}
  \vspace{0.8em}
  \begin{itemize}
    \setlength{\itemsep}{1.1em}
    \item \textbf{Node-level}: the prediction is $h_v$.\\

    \item \textbf{Edge-level}: the prediction is a function of $(h_u, h_v)$.\\

    \item \textbf{Graph-level}: a \alert{readout} sums or averages all nodes,

      {\small Is this scene graspable? Will this grasp succeed?}
  \end{itemize}

\begin{frame}{In multi-robot systems, a ``message'' is a real radio message}
  \vspace{0.8em}
  \begin{center}\large
    Nodes are robots. Edges are \alert{who is in communication range}.\\[0.6em]
    One round of message passing $=$ one round of radio traffic.
  \end{center}
  \vspace{1.0em}
  \begin{itemize}
    \setlength{\itemsep}{0.8em}
    \item Each layer costs one round of radio traffic per control step, so the
      \alert{radio bandwidth bounds the layer count}. \arx{1912.06095}
    \item In physics and manipulation, particles interact \alert{locally and
      identically}, which is what a shared message function assumes.
    \item So learned simulators generalize to \alert{more particles than the
      training set had}.
  \end{itemize}
\end{frame}
\note{The inductive bias matches the physical system here. Say both bullets
slowly. Both generalize beyond robotics.

    \begin{column}{0.46\textwidth}
      \footnotesize
      After enough rounds of averaging with your neighbors, \alert{each node
      in a connected graph holds the same vector}. Over-smoothing comes from the
      averaging itself, for any task.
      \vspace{0.5em}

      \textbf{Two caveats:}
      \begin{itemize}\setlength{\itemsep}{0.3em}
        \item The cliff mixes over-smoothing with the difficulty of
          \alert{deep GCN training} without residual connections.
        \item This is a toy task with a \emph{global} label, so extra hops help
          for longer than usual. On real benchmarks the optimum is
          \alert{2--3 layers}.
      \end{itemize}
    \end{column}
  \end{columns}
  \vspace{0.4em}
  \begin{center}\large
    Under either explanation, \alert{two layers} is the right starting point.
  \end{center}

\begin{frame}{When \emph{not} to use a GNN}
  \vspace{1.0em}
  \begin{itemize}
    \setlength{\itemsep}{1.0em}
    \item If the graph is \textbf{small and dense}, a Transformer is the better
      choice: the tooling is better, and on a complete graph it computes the
      same thing.
    \item If you \textbf{invented the edges} to make it a graph, you invented a
      prior, and it can be wrong.
    \item If the data is a \textbf{grid or a sequence}, a CNN or a Transformer
      already encodes that structure.
  \end{itemize}
  \vfill
  \begin{center}\large
    A GNN outperforms a Transformer when the \alert{interaction graph is
    sparse, known, and too large to learn from data}.
  \end{center}
\end{frame}
\note{This slide earns trust by showing when not to use the method.

Expected question: "are GNNs still relevant now that everything is a
transformer?" Answer: RoboBallet is from 2025, and the learned-simulator line
is active. If the interaction structure is known and sparse, an encoded graph
beats a learned graph, especially with limited data.}

\note{Q\&A prep:

* "Isn't a Transformer just a GNN?" -> Yes, on a complete graph. Use a GNN when
  you know the sparse structure and do not want to spend data on it.
* "How many layers?" -> Start at 2. Over-smoothing bites at 4. For long-range
  information, add a global node or a hierarchy. Do not add depth.
* "How do I build the graph for a point cloud?" -> k-NN with k around 16-20 in
  xyz, edge feature = relative position. DGCNN recomputes it in feature space
  each layer.
* "Do GNNs scale?" -> Neighbor sampling or graph clustering. Most robotics
  graphs are under 10k nodes, so you will not reach this limit.
* "Are GNNs still relevant?" -> RoboBallet (2025) and the learned-simulator
  line. A known, sparse structure beats a learned one, especially with little data.
* "Which library?" -> PyTorch Geometric. DGL for heterogeneous graphs.
* Out of scope on purpose: spectral graph theory / the Laplacian, the WL test
  and expressiveness, graph transformers, over-squashing, positional encodings,
  heterogeneous / temporal / knowledge graphs.}
